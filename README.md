# Search Control — поиск в списках Redmine как до 6.0

Плагин для Redmine 6.0+ (писался по исходникам 7.0.2).

## Что делает

В Redmine 6.0 список пользователей (*Администрирование → Пользователи*) перевели на фильтры запросов.
Старое поле «Пользователь» стало фильтром «Имя, email или логин», который нужно добавлять вручную, а
пустое значение даёт ошибку «не может быть пустым».

С плагином:

- фильтр **«Имя, email или логин» всегда стоит на странице** рядом со «Статус = активен»;
- **пустое поле — это «без фильтра»**, а не ошибка;
- если снять у фильтра галочку и нажать «Применить», поле вернётся (пустым);
- «Очистить» возвращает к «Статус = активен» и пустому полю;
- Enter в поле применяет фильтр (так делает сам Redmine).

Ищет так же, как старое поле: по логину, имени, фамилии и почте. Операторы «содержит», «не содержит»,
«начинается с» и прочие работают как раньше.

Шаблон страницы не меняется: патчится только `UserQuery` (фильтры по умолчанию, проверка пустого значения
и построение SQL). Настроек нет. Миграций БД нет.

## Установка

```bash
cd /opt/redmine/plugins
git clone https://github.com/man-from-podolsk/redmine_search_control.git   # папка должна называться redmine_search_control
chown -R www-data:www-data redmine_search_control
systemctl restart redmine        # юнит Puma
```

Обновление: `git pull` в папке плагина и перезапуск Puma.
Удаление: убрать папку из `plugins/` и перезапустить Puma.

Фильтры списка хранятся в сессии. Если после установки поле не появилось, нажмите «Очистить» или войдите заново.

## Проверка после установки

1. *Администрирование → Пользователи*: видны «Статус = активен» и пустое «Имя, email или логин», список показан без ошибки.
2. Ввести часть логина, имени или почты и нажать Enter: список отфильтрован.
3. Стереть значение и нажать «Применить»: снова все активные, ошибки «не может быть пустым» нет.
4. Снять галочку у фильтра имени и нажать «Применить»: поле вернулось пустым.
5. Добавить другой фильтр, например «Логин», с пустым значением: ошибка есть (плагин трогает только фильтр имени).
6. Выгрузка в CSV и API `/users.json?name=...` работают как раньше.

## Обновление

Раз в сутки модуль сверяет свою версию с GitHub и, если есть новая, показывает уведомление на страницах «Администрирование» и «Модули» (видят только администраторы): что изменилось
(из `CHANGELOG.md`) и как обновить. Запрос идёт с сервера Redmine на `api.github.com` и `raw.githubusercontent.com`
в фоне и не замедляет страницы. Проверить сразу: `bundle exec rake redmine:search_control:check_update RAILS_ENV=production`.

Если модуль установлен копированием:

1. Скачайте архив https://github.com/man-from-podolsk/redmine_search_control/archive/refs/heads/main.zip.
2. Переименуйте старую папку: `mv plugins/redmine_search_control /root/redmine_search_control.old`.
3. Распакуйте архив в `plugins/redmine_search_control` (папка в архиве называется `redmine_search_control-main`, её нужно переименовать),
   `chown -R www-data:www-data plugins/redmine_search_control`.
4. Если в `CHANGELOG.md` для новой версии сказано «миграция», выполните
   `bundle exec rake redmine:plugins:migrate NAME=redmine_search_control RAILS_ENV=production`.
5. Перезапустите Redmine.

Если установлен через `git clone`: `cd plugins/redmine_search_control && git pull` и перезапуск. Уведомление в этом случае
считает новые коммиты, а не версии.
